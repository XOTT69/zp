# Калькулятор ЗП 2/2

SPA-калькулятор зарплати для ролей:

- `/service` - ЗП оператора сервісу
- `/supervisor` - ЗП СВ
- `/level4` - ЗП 4 лвл
- `/xd` - ЗП ХД
- `/video` - ЗП відеоверифікатора
- `/iron` - ЗП операторів IRON з перемикачем графіка 2/2 та 5/2
- `/admin` - адмін-панель зі статистикою входів, переглядів, копій і PDF

## Безпека

Авторизація працює через Vercel serverless API та Routing Middleware:

- `/api/login` перевіряє код ролі на сервері;
- `/api/session` повертає тільки дозволені для ролі калькулятори та ставки;
- `/api/logout` очищає сесію;
- `/api/page` віддає `index.html` тільки після серверної перевірки маршруту;
- `middleware.js` не пускає на закриті маршрути без валідної cookie;
- у клієнтський JS не віддаються ставки чужих ролей.

Коди ролей потрібно задати у Vercel Environment Variables:

- `OPERATOR_ACCESS_CODE`
- `SUPERVISOR_ACCESS_CODE`
- `LEVEL4_ACCESS_CODE`
- `XD_ACCESS_CODE`
- `VIDEO_ACCESS_CODE`
- `IRON_ACCESS_CODE`
- `ADMIN_ACCESS_CODE`
- `AUTH_SECRET`

`AUTH_SECRET` має бути довгим випадковим рядком. Після зміни env-змінних потрібно зробити redeploy.

Для адмін-панелі задайте окремий довгий випадковий `ADMIN_ACCESS_CODE`. Не зберігайте
реальне значення коду в репозиторії або документації.

Вхід обмежений до 10 спроб на IP і роль протягом 15 хвилин. Якщо підключений
Upstash Redis, ліміт працює між усіма serverless-інстансами; без Redis діє
локальний захист у межах поточного інстансу.

Для статистики, яка не зникає після redeploy або холодного старту Vercel, підключіть Upstash Redis і додайте:

- `UPSTASH_REDIS_REST_URL`
- `UPSTASH_REDIS_REST_TOKEN`

Якщо Redis не підключений, адмін-панель усе одно відкриється, але статистика буде тимчасовою.

## Калібрування прогнозу виплат

В адмін-панелі є блок `Правила виплат по місяцях`. Туди можна внести фактичні виплати за місяць:

- сума і години 15 числа;
- сума і години 31 числа;
- сума 07 числа;
- сума стажу.

Після збереження калькулятор підтягує ці правила через API без нового деплою. Для постійного збереження правил потрібен Upstash Redis.

## Керування ставками

JSON ставок і шаблонів проходить серверну перевірку: невідомі напрямки, поля, місяці та значення поза допустимими межами не зберігаються. Перед кожною зміною створюється знімок попередніх налаштувань. В адмін-панелі його можна відновити через блок `Історія ставок і шаблонів`.

Клієнтський код розділено на модулі в `modules/`: авторизація, локальне збереження, UI калькулятора, звіти, безпечний HTML та адмін-панель.

## Перевірка формул

```bash
npm run verify
```

Скрипт перевіряє операторів, СВ, 4 лвл, ХД, відеоверифікатора та IRON на контрольних прикладах.

## Локальний запуск

Для повної перевірки авторизації потрібен Vercel dev/runtime, бо сайт використовує `/api/*` та `middleware.js`.

Статичний сервер показує лише HTML/CSS/JS, але не виконує Vercel API:

```bash
npm run dev
```

## Деплой на GitHub + Vercel

1. Створіть репозиторій на GitHub і запуште файли проєкту.
2. У Vercel натисніть `Add New Project`.
3. Оберіть GitHub-репозиторій.
4. Framework Preset: `Other`.
5. Додайте env-змінні з розділу `Безпека`.
6. Build Command залиште порожнім.
7. Output Directory залиште порожнім або `.`.
8. Натисніть `Deploy`.
