# Калькулятор зарплати

13 напрямків: сервіс, СВ, 4 LVL / ментори, ХД, відео, IRON, СЗ, пСЗ, МСБ, МЕО, ФМ, консьєрж і софт. Кожен авторизований користувач може переглядати всі напрямки й порівнювати зарплати. Адміністратор окремо керує ставками та статистикою.

## Можливості

- Порівняння всіх напрямків за однаковими годинами, кольором зони, рівнем і стажем. Непорівнювані зони/графіки позначаються; враховуються лише доступні конкретному напрямку доплати.
- Основні ставки для 12 напрямків — із калькулятора колеги, за рішенням власника проєкту. Попередні правила доступні окремо для порівняння. Відео залишено за нашими правилами — такого напрямку в джерелі немає.
- Окремі ставки до/після 3 місяців для сервісу, МСБ, МЕО, ФМ, консьєржа й софту в наборі колеги. Функціональна надбавка софту та залежність кваліфікації від зони.
- Години `8,5`, `8.5`, `8:30`; пояснення десяткових значень та перевірка помилок.
- До 30 збережених розрахунків кожного напрямку, до 6 спільних сценаріїв. Нові записи зберігають результат і копію ставок. Старі записи без копії ставок показують збережену суму й не перераховуються мовчки. Попередні сценарії мігруються без видалення старих даних.
- Звичайні поля окладу, рейтингу й кваліфікації в адмінці, чернетка та перегляд впливу до збереження; JSON доступний окремо.
- Дата набуття чинності ставок і вибір версії за місяцем. Наразі підтримується 2026 рік; інші роки блокуються, доки не додано відповідні норми. Непідтверджений календар виплат приховано.
- Компактна форма, підписані кольори, адаптивний підсумок, звіт для копіювання/PDF, manifest для додавання сайту на головний екран. Офлайн-розрахунок не реалізовано.

## Джерело ставок

Див. [звірку](docs/RATE-AUDIT.md) і [контрольну таблицю](tests/fixtures/colleague-2026-09.json). Власник проєкту підтвердив, що калькулятор колеги правильний, і вибрав його основним джерелом. Це рішення щодо правил проєкту; окрема звірка з таблицями виплат компанії не виконувалася. Робочі форми наявних користувачів одноразово переходять на основне джерело, після чого явний вибір попередніх правил зберігається. Історія та сценарії зі знімками ставок не змінюються.

Адміністративні перевизначення й шаблони попередньої версії не замінюють основні ставки колеги. Редактор ставок продовжує керувати попереднім набором і відеоверифікацією; це позначено у формі.

## Вхід та збереження

Збережено серверний вхід за кодом ролі. Додано корпоративний логін із одноразовим кодом у Slack: [інструкція підключення](docs/CORPORATE-LOGIN.md), [Slack App manifest](docs/slack-app-manifest.json), [.env.example](.env.example).

Секрети зберігаються лише в Environment Variables. Увесь набір зарплатних правил доступний авторизованим користувачам за погодженою політикою спільного перегляду. Cookie не містить паролів. Для персональних LDAP-акаунтів локальні записи розділені за користувачем. Історія входу за спільними кодами ролей залишається спільною в межах браузера. Локальна історія доступна в цьому браузері, не синхронізується між пристроями й не очищується при виході; на спільному пристрої її можна очистити кнопкою.

Для постійних ставок, статистики й входу через Slack використовується Upstash Redis. Production не дозволяє зберігати правила без постійного сховища. Помилка завантаження налаштувань блокує новий розрахунок. Редагування/відкат ставок доступні адміністратору; відкат історичного періоду потребує перевірки дати чинності.

## Розробка

Node.js 22 або новіший:

```bash
npm ci
npm run dev
npm run verify
```

Локальний сервер: `http://127.0.0.1:4174`. Код ролі для цього локального сервера — `local-preview`, якщо відповідна env-змінна не задана. Він слухає лише localhost. Цей резервний код відсутній у production API. Не запускайте preview зі справжніми корпоративними секретами без потреби.

Тести перевіряють старі контрольні приклади, матриці нових ставок, частковий місяць, доплати, валідацію, історію, вибір версій, доступ до всіх напрямків і ізольовану логіку корпоративного входу. Реальний LDAP/Slack/Redis перевіряється після підключення інфраструктури.

## GitHub та Vercel

Залишено наявну архітектуру Vercel: Framework `Other`, Node 22+, без build command, каталог виводу — корінь. Змінні з `.env.example` налаштовуються окремо для Preview та Production. Після зміни змінних потрібен redeploy. Гілки/PR використовуються для попереднього перегляду; production оновлюється після злиття в основну гілку.

Корпоративний вхід об’єднано в одну функцію `/api/corporate-auth`: GET — доступні способи; POST `action=request` / `action=verify`. Без налаштування інтеграції він вимкнений. Доступність і придатність тарифу Vercel для корпоративного використання перевіряйте за поточними умовами постачальника.

## Автоматичні перевірки GitHub

Готовий шаблон: `docs/github-workflow-verify.yml`. Для ввімкнення його потрібно додати як `.github/workflows/verify.yml` через GitHub або токен із правом `workflow`. Поточна OAuth-авторизація дозволяє зміни коду, але GitHub відхилив запис workflow; тому Actions ще не активовано. Локальна команда `npm run verify` працює незалежно від цього.
